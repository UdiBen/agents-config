# Test Audit

A test earns its place by catching a credible regression no other test catches. Everything
here applies that bar.

- **Authoring**: every new or changed test passes the gate below.
- **Audit**: prune low-value proof in coherent owner batches; read
  [references/audit.md](references/audit.md) before the first edit.
- **Campaign** (one subsystem's whole test surface in one PR): read
  [CAMPAIGN.md](CAMPAIGN.md) first.

The repo's own instructions (`AGENTS.md`, `CLAUDE.md`, testing docs) own the commands for
running tests, changed-file checks, and CI routing. Read them before validating.

## Authoring gate

Before adding or changing a test, answer:

1. What observable behavior, invariant, or independent contract does it protect?
2. What credible regression makes it fail?
3. Why does existing proof miss it? Each contract has one primary owner at the strongest
   boundary. A second layer needs a distinct transport or lifecycle risk. Extend existing
   tables and shared fixtures; consolidate repeated setup.
4. Does it need an export, flag, wrapper, or injection hook with no production caller? Move
   the proof to the real boundary instead.

- A regression test goes red before the fix for the intended reason and green after it.
  Report when that baseline proof was unavailable.
- One regression at the owner covers a bug. Replaying it at every layer it crosses adds
  cost, not proof.
- A behavior-preserving refactor leaves the test green.

## Junk patterns

Reject these on sight:

- self-comparisons, copied inventories, source greps
- implementation or call-shape assertions
- duplicate contracts and test-only seams
- expected values generated by the subject under test
- mocks that supply the behavior being asserted
- fixtures that fabricate owner receipts or ordering, or assert persistence on a path the
  code never writes
- negative controls that pass on an unrelated guard
- names promising behavior the test never exercises

The full audit checklist is in [references/audit.md](references/audit.md#junk-patterns).

## Retention bar

- Keep independent contracts: public API, SDK, protocol, config, migration, storage,
  security, platform, defaults, generated cross-language output, package, release,
  architecture, and observable ordering. Static or slow is never a deletion reason.
- Source inspection stays only when it survives identifier-only refactors and guards an
  independent user-facing contract.
- A baseline failure may be a product bug: reproduce and repair it at the owner.

## Report

- causes and removed categories
- retained contracts
- proof run and its cost
- production LOC versus test/support LOC
- follow-ups

Commit, push, or land only with the authority the task grants.
