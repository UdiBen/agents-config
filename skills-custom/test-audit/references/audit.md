# Audit workflow

Audits are read-only until the candidate evidence is recorded and reported. The
[authoring gate](../SKILL.md#authoring-gate) and
[retention bar](../SKILL.md#retention-bar) apply to every candidate. Whole-subsystem
campaigns also follow [CAMPAIGN.md](../CAMPAIGN.md).

## Junk patterns

Reject new matches unless the retention bar names an independent contract. Audit existing
matches:

- assertion-free probes, self-comparisons, identity copiers
- expected values generated by the subject under test
- copied inventories, manifests, or export lists
- exact source, import, or string greps
- private predicate or call-shape tests duplicating boundary proof
- repeated invocations of a shared helper replayed per caller
- test-only exports, globals, or wrappers; production paths called only by tests
- mocks implementing the asserted behavior, or pretending distinct APIs match
- fixtures supplying receipts, admission, or callback ordering the owner should produce
- persistence asserted against a store path the code never writes
- capability flags asserted instead of the promised delivery or acknowledgement
- negative controls passing on an unrelated guard or an unreachable rejection
- names promising behavior the inputs and assertions never exercise

## Candidate evidence

Before editing, read the full test, its production owner, entry point, callers, callees,
siblings, overlapping proof, CI routing, and history. For dependency-backed claims, read
the dependency's source or types.

Record for each candidate:

- exact name and location, and the failure it detects
- non-test callers of the production or support seam it covers
- the stronger proof that remains, or why none is needed
- why it exists (history) and what deleting it unlocks
- risk, and the focused command that validates the change

Missing evidence means no deletion. Prefer a few high-confidence candidates over a long
speculative list. Parallel discovery may split along independent owners.

## Editing

- Delete obsolete seams and dead paths along with their tests.
- Move retained regressions to their owner; consolidate generic dependency contracts.
- Prefer net-negative production LOC.
- Uncertainty stays a reported follow-up; it never becomes cleanup or a replacement test.

## Validation and handoff

- Run owner and sibling tests with the repo's documented commands.
- A removed source grep or plan assertion gets replaced by exercising the owning executable
  or its dry-run.
- Run the repo's formatter and changed-file checks, plus `git diff --check`.
- Inspect `git diff --numstat`, then get a final review of the diff.
- Report per the [SKILL.md report](../SKILL.md#report), plus retained false positives and
  PR state.
- Refresh from the main branch and rediscover before starting another audit batch.
